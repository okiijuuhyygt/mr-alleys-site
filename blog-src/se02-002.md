先講答案：Melodyne 修完音存檔重開卻打回原形，這叫 ARA 掉連結，不是你手殘。原因通常是專案搬過位置、路徑變了，或那段音訊被剪接過，Melodyne 認不得原本那段了。搶救法是趁還看得到編輯資料時，立刻 Bounce in Place 印成 audio；根本解是修完一段就印一段，別讓外掛狀態過夜。

## 先看資料還在不在，能不能救

先別急著關檔，也別急著重修一次。打開 Melodyne，看左側的片段列表，點一下上面那個片段的圖示（不是你正在編輯的那個當前片段），看修音資料是不是還躺在那裡。找到了，立刻按 Bounce in Place（Ctrl+B），把修過的結果印成一軌獨立的 audio。印成 audio 就跟外掛脫鉤了，之後專案再怎麼搬、外掛再怎麼更新，都不會再掉。如果是專案搬移造成的斷線，有時候重新掃描一次 ARA 外掛也救得回來，值得先試這招再放棄。

## ARA 到底是什麼、為什麼說斷就斷

ARA 是讓 Melodyne 這種外掛直接讀你 Logic 音軌、跟主機共用同一條時間軸的技術，好處是不用另外 render 一次就能即時修音，省事又直覺。但它記住的是「哪一段音訊、在哪個位置」這組對應關係，是靠路徑跟 Region ID 認人的，不是靠耳朵認聲音。專案一搬家、路徑變了，或你把那段 Region 剪開、Region ID 因此亂掉，這組對應關係就斷了，Melodyne 就找不到自己修過的東西，修音資料當然回不來。如果你遇到的其實是 Logic 突然按不動 Undo，那通常是另一個 Melodyne 或 Flex 模式的陷阱，[Logic Pro 突然不能 Undo 了](/blog/se02-006/) 那篇有講怎麼判斷。

## 我踩過雷才學會的三條保命鐵律

第一，不要在 Take Folder（一堆錄音疊在同一軌的那種資料夾）狀態下直接用 ARA，先 Flatten 攤平成一條乾淨的音軌再修。Take Folder 底層的結構本來就比較複雜，ARA 認人更容易認錯。第二，修音修完之後就不要再剪接那段 Region 了，一剪，Melodyne 的 Region ID 就錯亂，等於自己把連結線剪斷。第三，修完一段就馬上 Bounce 一段，不讓外掛狀態過夜，這是最重要的一條，養成習慣之後，掉連結這件事基本上不會再發生在你身上。這三條沒有一條是我一開始就懂的，全部是先掉過資料、心痛一次之後才變成反射動作。

## 常見問答

**Melodyne 掉連結，修過的音準真的救不回來嗎？**
只要編輯資料還在片段列表裡就救得回來，重點是先別關檔、別重修，找到那個片段圖示立刻 Bounce in Place。真的找不到資料才需要重修一次。

**為什麼我明明沒搬專案，也會掉連結？**
最常見是你剪接了那段 Region，剪一刀 Region ID 就變了，Melodyne 對不上號。修完的段落盡量別再動剪輯，要剪就先剪好再進 Melodyne。

**Bounce in Place 之後音質會變差嗎？**
不會，Bounce in Place 印出來的是原本的音訊加上你的修音結果，格式不變。真正該注意的是印完之後外掛連結就沒了，之後想再微調那段音準，要重新拉 ARA 或直接動印好的那軌波形。
