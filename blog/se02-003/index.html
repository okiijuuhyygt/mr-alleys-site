Logic 專案檔越開越肥、載入越來越慢？我怎麼幫專案瘦身

陳則皞2026-08-01Logic Pro 與 DAW 技巧

先講答案：Logic 專案開越久越肥、載入越來越慢，多半是裡面塞了一堆你早就不要的錄音 take。用內建的清理專案功能把沒用到的音檔移掉，再把修好的 Melodyne、Flex 段落 Bounce in Place 印成 audio，檔案立刻瘦一圈，開檔也快。

我固定做的瘦身動作

混到一個段落，我會用 File 選單裡的專案清理功能，把沒被任何 Region 引用的音檔挑出來刪掉（Logic 會列給你看，勾一勾就好）。修完音的軌我一定 Bounce in Place，把 Melodyne 的即時運算換成一軌純 audio，CPU 跟檔案大小都省。真的想留原始 take，就另存一個「錄音備份版」專案，再清主檔，兩全其美。要注意的是，Melodyne 用 ARA 接的軌一旦 Bounce 就不能回頭再修音高了，存檔重開就掉連結那件事我另外寫過（Melodyne 修完音，存檔重開就不見了），清理前先想清楚這軌還要不要再改。

專案為什麼會胖

一首歌錄人聲，常常同一段唱十幾次，每個 take 都是一個完整音檔，全躺在專案的 Audio Files 資料夾裡。你最後只留一版，但另外十幾版沒被刪就一直佔空間。加上 Melodyne、Flex 這類即時處理會讓 Logic 一直在背景運算，專案越大跑起來越吃力。這跟電腦效能沒有直接關係，是專案裡堆的東西變多了，運算量自然跟著往上疊。

順手養成的習慣

我會在專案名後面標日期或版本（像 v2、mix0705），清理前先複製一份，這樣就算清錯也有退路。專案瘦下來的好處不只開檔快，交接、上傳、備份到雲端都輕鬆很多，尤其是你要把檔案傳給別人混音的時候。如果你發現不只開檔慢，連 Undo 都會卡住，那通常是另一個問題，可以先看看是不是在 Melodyne 或 Flex 模式底下操作（我寫過Logic 突然不能 Undo 了）。

常見問答

清理專案功能會不會不小心刪到我還要用的音檔？
不會，它只挑出「沒被任何 Region 引用」的音檔，也就是專案裡看不到、用不到的那些。真正在軌道上的音檔不會被列進去，但保險起見我還是會先複製一份專案再清。

Bounce in Place 之後，音檔還能再修嗎？
可以剪接、可以調音量，但 Melodyne 的即時音高修正會固定住，之後想改音高得回到原始 take 重修。所以我通常會等一個段落確定不再動了才 Bounce。

專案多久清理一次比較好？
沒有固定週期，我習慣在每次進到混音、覺得開檔明顯變慢的時候清一次。與其定期清，不如養成「錄完就砍多的 take」的習慣，專案本來就不會胖太快。
